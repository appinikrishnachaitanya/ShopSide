# Move-In Studio implementation plan

Preserve the general shopping flow and runtime proxy. Add an opt-in move-in room mode; keep validated mission data and explicit participant decisions in the existing room JSON state so existing PostgreSQL data and migrations remain intact. Use the configured Gemini client for structured mission extraction and limit follow-up questions in server code. Use Channel3 for real products, with retailer links separate from sandbox inventory. Record item-level approvals and exact-cent cost shares as agreements only. Reuse room membership, revision checks, idempotency and WebSocket snapshots. Add a small fictional home catalog to the existing eligible sandbox inventory. Employer administration needs an independent identity and authorization boundary; do not expose private room state or claim a real employer integration. Validate with mocked backend tests, frontend build, two-browser tests and available live provider checks. Keep a single API instance until shared pub/sub and locks exist. No commit, push or deployment before review.
