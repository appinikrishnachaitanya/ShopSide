# Move-In Studio: verification and remaining work

Move-In Studio is an opt-in room mode alongside general shopping. It stores structured, editable mission state and decisions in the existing room JSON; no destructive data migration or new relational schema is needed. The configured Vertex AI express account successfully extracted the $500 budget from a sample mission. Gemini's follow-up count is enforced on the server at four, and manual editing remains available when the provider fails.

The focused fictional home-essentials catalog uses the existing USD PayPal Sandbox merchant flow. Channel3 products remain retailer-only, with original offer URLs. A real sandbox order was created for a fictional lamp using the configured PayPal account; it was not approved or captured. A buyer must approve the order in PayPal before capture and read-back can be verified. There is no claim of shipped goods or a third-party purchase.

Validation at review: backend tests passed (28 passed, one skipped), Next.js production build passed, and two independent desktop/mobile browser room tests passed, including shared move-in approvals and refresh. SQLite Alembic migrations were applied to a disposable database. Prior live Channel3 conversation, detail, similar and search checks succeeded; no new live test establishes external checkout. Cloud SQL connectivity and a live two-browser call were not verified in this change. TURN remains necessary on restrictive networks. WebSocket subscribers, locks and signaling are process-local: use one API instance and one worker.

## Not yet complete

The illustrative Relocation Desk uses a separate administrator bearer token and an AG Grid ledger containing only verified sandbox purchase summaries; it does not return private room chats or calls. Policies are shared through a private allocation code, which is reusable and should be treated as a bearer capability. This is a single-administrator illustrative flow, not a production employer identity or tenancy system; there is no HRIS/payroll integration. Checkout rejects ineligible products and those over the approval threshold; the administrator approval workflow itself is not implemented. The current eligibility check supports the fictional merchant catalog, where category and USD price are known; it does not invent categories or charges for Channel3 offers. Real sandbox buyer approval and capture, verified receipt reconciliation end to end, automated voice-media verification, remain to be completed. The cost share is a shared record, not a payment or proof that each person accepted the allocation. The AI compromise button uses the existing decision agent; the suggested options need live end-to-end validation with two real preferences and live products. Search uses country and currency where supplied, but other provider-supported integrations such as URL lookup and price history remain deferred. Per-item status becomes purchased only after a verified ShopSide sandbox capture; an outbound retailer visit never marks an item purchased.

## Three-minute walkthrough

1. Choose **Move-In Studio**. Enter “We're moving next Friday and need a home office and kitchen under $500,” then create a room. Review the extracted mission and correct any details.
2. Choose **Find essentials with Channel3**. Review real product cards and retailer offers; focus an item, explore details or similar products, and add it to the shared plan.
3. Invite a second person. Each person enters their preference, optionally uses the decision assistant, and explicitly approves the same plan item. The timeline and approval state appear to both people.
4. For the fictional home lamp, add the item to the shared cart. The designated payer reviews the exact USD sandbox quote and approves through PayPal. If approved, capture and check the provider status; never represent this as a purchase of an external Channel3 product.

## Shared 3D room

The Move-In workspace includes a Three.js room. Either room member can focus a catalog or Channel3 product, choose a position in the preview, and move or remove its shared marker. Placements are persisted in the existing room state and broadcast through the existing room WebSocket, with membership, command idempotency and revision checks. The room and markers are illustrative; Channel3 listings do not supply verified 3D models or dimension data in this integration, so the preview cannot establish that an item fits. If WebGL is unavailable, the placement list and center-placement controls remain usable. No new environment variable or schema migration is required for the room preview.
